## 0. Ringkasan proyek

- **Apa:** game latihan *cable hero* MOBA (gaya Fanny di Mobile Legends) dengan karakter **stickman**. Fokus utama:
  latihan **straight cable** (melempar kabel lurus tepat ke dinding, merangkai kabel, rute cepat), dengan rasa gerak
  yang **sangat halus** (target 60–120 FPS stabil, input tanpa lag).
- **Kamera:** dari atas, miring, tetap (tidak berputar), mengikuti hero — **semirip mungkin dengan kamera MOBA mobile
  pada umumnya**. Detail di `docs/GAME_SPEC.md` §3.
- **Platform utama:** Android (landscape, layar sentuh). Sekunder: Linux64 (untuk dicoba di laptop owner) dan Windows.
- **Engine:** Unity **6000.3.29f1** (Unity 6.3 LTS), C#, URP, Input System.
- **Repo:** `github.com/Kodok-Kejepit/Stickman-Project` (**PUBLIK**). Folder lokal: `~/Project/Stickman-Project`.
- **Owner:** Kodok-Kejepit. Owner bukan programmer Unity. Jelaskan dengan bahasa sederhana.

## 3. Build & CI (WAJIB)

- **JANGAN build di laptop.** Laptop owner RAM-nya kecil (±7 GB) dan dipakai untuk hal lain. Dilarang:
  `Unity -batchmode -buildTarget ...`, `BuildPipeline.BuildPlayer` lokal, export APK/EXE lokal, install Android SDK lokal.
- **Build = push ke `main`.** GameCI (`.github/workflows/build.yml`) menjalankan tes EditMode lalu build:
  Android (APK), StandaloneLinux64, StandaloneWindows64.
  - Manual: `gh workflow run build.yml -R Kodok-Kejepit/Stickman-Project --ref main`
  - Pantau: `gh run list -R Kodok-Kejepit/Stickman-Project -L 3`
  - Log gagal: `gh run view <id> -R Kodok-Kejepit/Stickman-Project --log-failed`
  - Unduh hasil: `gh run download <id> -R Kodok-Kejepit/Stickman-Project -n StickmanProject-Android -D <folder>`
- Image Docker dipatok `unityci/editor:ubuntu-6000.3.29f1-<platform>-4` lewat `customImage`
  (`unity-builder@v4` sendiri mencari revisi `-3` yang TIDAK ADA untuk versi ini). `unity-test-runner` dipatok
  **v4.3.2** (v4.4.0 gagal aktivasi lisensi di Unity 6). **Jangan diubah** kecuali tahu persis alasannya.
- Ganti versi Unity = DILARANG tanpa izin owner.
- Workflow otomatis dilewati selama belum ada `ProjectSettings/ProjectVersion.txt` (proyek Unity belum dibuat).
- **Jangan menunggu CI dengan polling yang boros.** Satu perintah tunggu (`gh run watch <id> --exit-status` atau
  loop `sleep 60`) yang berjalan di background sudah cukup.

### Unity batchmode lokal (hanya untuk skrip editor ringan)

Boleh menjalankan editor dalam batchmode untuk: membuat proyek pertama kali, generate `.meta`, menjalankan builder
scene/data (skrip `Assets/Editor/*Builder.cs`). **Selalu** dengan batas memori + timeout + stdin tertutup:

```bash
systemd-run --user --scope -q -p MemoryMax=3200M -p MemorySwapMax=0 \
  timeout 900 ~/Unity/Hub/Editor/6000.3.29f1/Editor/Unity -batchmode -nographics -quit \
  -projectPath ~/Project/Stickman-Project -executeMethod <Namespace.Class.Method> -logFile - < /dev/null
```

- Cek lokasi editor dulu (`ls ~/Unity/Hub/Editor/` atau `unity editors --installed`), jangan menebak path.
- **Jangan pernah** menjalankan perintah yang menunggu input (tanpa `< /dev/null`) atau tanpa `timeout` —
  dulu pernah ada perintah yang menggantung 4 jam karena ini.
- Kalau editor Unity owner sedang membuka proyek ini (ada `Temp/UnityLockfile`), JANGAN jalankan batchmode; minta
  owner menutupnya. Jangan membunuh proses editor owner.

## 5. Standar kode Unity

### Struktur folder

```
Assets/
  Scenes/            Boot.unity (scene pertama), Practice.unity, ...
  Scripts/
    Core/            GameBootstrap, FrameRate, Settings, SaveData, Loc
    Hero/            HeroMotor, CableSkill, SpinSkill, DashSkill, Energy, HeroState
    Camera/          MobaCamera
    Input/           TouchJoystick, SkillButton, AimStick, InputRouter
    Practice/        Drill, Course, Checkpoint, WallTarget, Stats, GhostReplay
    UI/              HUD, menus, layout editor
  Data/              ScriptableObject (HeroTuning, CameraTuning, DrillData)
  Editor/            builder scene/data, tools
  Tests/EditMode/    tes Unity Test Framework (+ .asmdef)
  Resources/         hanya yang benar-benar perlu dimuat runtime
```

### Aturan

- Namespace `Stickman.<Folder>` (mis. `Stickman.Hero`). Satu `MonoBehaviour`/`ScriptableObject` per file, **nama
  file = nama class** (kalau beda, Unity gagal menyerialisasi).
- Semua angka tuning (kecepatan kabel, jarak, biaya energi, pitch kamera, dll.) **di ScriptableObject**, bukan
  hard-code, supaya owner bisa menyetel tanpa ubah kode. Nilai default awal ada di GAME_SPEC.
- Logika murni (matematika kabel, energi, skor) dipisah ke class/fungsi statis tanpa `MonoBehaviour` → bisa dites.
- **Performa (ini game "smooth"):**
  - Nol alokasi GC per frame di jalur panas (`Update`, input, kamera). Tidak ada LINQ, `new List`, string concat,
    `GetComponent`, `FindObjectOfType` di dalam `Update`. Cache referensi di `Awake`.
  - Gunakan `Physics.Raycast`/`SphereCast` NonAlloc untuk kabel.
  - Gerak hero di `Update` dengan interpolasi yang benar, atau `FixedUpdate` + `Rigidbody.interpolation`
    — pilih satu, konsisten, dan dokumentasikan di `docs/DECISIONS.md`. Kamera bergerak di `LateUpdate`.
  - `Application.targetFrameRate` mengikuti refresh rate layar (60/90/120), `QualitySettings.vSyncCount = 0` di
    mobile. Ada opsi FPS di Settings.
  - Tidak ada `Debug.Log` di build rilis pada jalur panas.
- **URP:** jangan pakai `GameObject.CreatePrimitive` saat runtime tanpa mengganti material ke material URP —
  di build hasilnya MAGENTA. Siapkan material URP di `Resources/` dan pakai itu.
- UI: uGUI (Canvas) untuk kontrol sentuh dan HUD. Multitouch wajib (joystick + tombol skill bersamaan).
  Hormati *safe area* (poni/notch HP).
- Jangan meninggalkan kode mati, TODO tanpa catatan, atau fitur setengah jadi di `main` tanpa ditulis di PROGRESS.

### Tes (WAJIB)

- Setiap logika inti punya tes EditMode di `Assets/Tests/EditMode` (berjalan di CI).
  Minimal: arah & jarak kabel, kabel kena/tidak kena dinding, biaya & regen energi, rantai kabel, skor akurasi
  straight cable, matematika kamera (posisi/offset), simpan/muat pengaturan.
- Tes "aturan proyek": nama file = nama class, tidak ada `CreatePrimitive` tanpa material URP, semua scene terdaftar
  di Build Settings.
- CI merah = **perbaiki dulu** sebelum lanjut fitur lain.

## 6. Verifikasi — jangan tebak-tebakan (WAJIB)

Owner sudah kecewa sebelumnya karena hasil yang "katanya jalan" ternyata rusak di layar (gambar gepeng, objek
magenta, UI bertumpuk). Maka:

1. **Tes EditMode hijau di CI** — wajib, tapi BELUM cukup.
2. **Jalankan build sungguhan** (unduh artefak Linux64 dari CI) di laptop dan **ambil screenshot, lalu LIHAT sendiri**
   gambarnya sebelum lapor. Buat harness di game:
   - `-autoshot <folder>` → game berjalan sendiri melalui rute (menu → practice → lempar kabel → rantai → course),
     menyimpan screenshot PNG + `diag.txt` (FPS rata-rata, frame time p99, resolusi, error).
   - `-selftest <folder>` → menjalankan semua fitur otomatis, menulis `errors.txt` (harus kosong) dan `log.txt`.
   - `-touch-ui` → memaksa tampilan kontrol sentuh di PC agar layout HP bisa diperiksa.
3. Periksa di screenshot: proporsi tidak gepeng (aspect ratio benar), tidak ada magenta, UI tidak bertumpuk / terpotong,
   tombol tidak keluar layar, teks terbaca, kamera sudutnya benar.
4. Laptop owner memakai Hyprland (Wayland) dengan skala 1.2 → layar logis ±1600×900. Jalankan build dengan
   `-screen-fullscreen 1 -screen-width <W> -screen-height <H>` sesuai `hyprctl monitors -j` (lebar/skala), agar tidak
   gepeng. Screenshot layar asli bisa dengan `grim`.
5. Hal yang hanya bisa dinilai di HP (rasa sentuh, latensi, panas) → katakan jujur "belum dicoba di HP".
